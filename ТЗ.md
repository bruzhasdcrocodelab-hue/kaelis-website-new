# **ТЗ: техническое SEO kaelisai.com**

Nov 2, 2026 · @Oleksandr Vesilyk

## **Контекст**

Сайт на Next.js (App Router, хостинг Vercel) отдаёт поисковикам почти пустые страницы, не имеет robots.txt и sitemap.xml и плодит бесконечные дубли на любые URL. Всё ниже проверено запросами curl к продакшену 2 ноября 2026 года, в том числе с user-agent Googlebot, без выполнения JavaScript.

Проверенные URL: /ru, /ru/tarot, /ru/tarot/dreams, /en/tarot/dreams, /ua/tarot/dreams, /robots.txt, /sitemap.xml и намеренно неверные варианты (/ru/tarot/dreams-xyz, /ru/tarot/DREAMS, /RU/..., /es/...). Отрендеренную версию в Google Search Console не проверяли: доступа к ней нет.

## **Сводка задач**

P0 блокирует нормальную индексацию: эти задачи нужно закрыть первыми. P1 влияет на ранжирование и CTR, P2 улучшает скорость.

| \# | Приоритет | Задача | Где |

| 2 | P0 | Отдавать sitemap.xml со всеми страницами и hreflang (сейчас 404\) | app/sitemap.ts |

## **Задачи 1–2. robots.txt и sitemap.xml**

**Сейчас.** /robots.txt и /sitemap.xml возвращают 404 с HTML-страницей ошибки Next.js. Запрос ловит динамический роут \[locale\], который принимает robots.txt за локаль. Страница ошибки при этом содержит \<meta name="robots" content="noindex"\> и lang="en".

**Почему важно.** Без sitemap поисковики находят страницы раскладов только по ссылкам, а в серверном HTML ссылок на них нет (задача 6). Без robots.txt нельзя указать sitemap и закрыть служебные пути.

**Что сделать.**

1. Создать app/robots.ts через Metadata API. Ответ: text/plain, статус 200\.  
2. Создать app/sitemap.ts. Включить все локали (en, ru, ua) для главной, хаба /tarot и каждого расклада. Для каждого URL указать alternates.languages (hreflang en, ru, uk, x-default), как уже сделано в \<head\>.  
3. Исключить robots.txt, sitemap.xml, favicon.ico и статику из матчинга \[locale\]: через matcher в middleware или проверку locale по списку поддерживаемых с вызовом notFound().

Пример robots.txt:

User-agent: \*  
Allow: /  
Disallow: /api/

Sitemap: https\://kaelisai.com/sitemap.xml  
Не закрывайте в robots.txt /\_next/ и API, из которого грузится контент расклада: без них Google не отрендерит страницу.

## **Задачи 3–4. Soft 404 и дубли по регистру**

**Сейчас.** Роут /\[locale\]/tarot/\[...slug\] отвечает 200 на любой slug. На каждый такой URL ставится собственный canonical и полный набор hreflang, то есть поисковик получает бесконечное число «уникальных» страниц.

| URL | Статус | title | canonical |
| :---- | :---- | :---- | :---- |
| /ru/tarot/dreams | 200 | Таро сновидений \| Kaelis | на себя |
| /ru/tarot/dreams-xyz (не существует) | 200 | Kaelis | на себя |
| /ru/tarot/DREAMS (дубль) | 200 | Kaelis | на себя |

**Почему важно.** Google помечает такие страницы как soft 404, тратит на них краулинговый бюджет и может склеить их с настоящими страницами. Любая битая внешняя ссылка создаёт новую индексируемую страницу.

**Что сделать.**

1. В generateMetadata и в самой странице проверять slug по списку существующих раскладов. Неизвестный slug → notFound(), HTTP-статус 404\.  
2. В middleware делать 308-редирект пути в нижнем регистре: /ru/tarot/DREAMS → /ru/tarot/dreams.  
3. Canonical и hreflang строить только из нормализованного slug из справочника раскладов, а не из входящего URL.

Проверка: curl \-s \-o /dev/null \-w '%{http\_code}' https\://kaelisai.com/ru/tarot/dreams-xyz должен вернуть 404.

## **Задачи 5–6. Контент и ссылки в серверном HTML**

**Сейчас.** На /ru/tarot/dreams сервер отдаёт около 35 КБ HTML, где вместо контента стоит заглушка «Загрузка…». В HTML нет ни одного тега H1–H3. Текста расклада нет и в RSC-payload: там только title и description, а контент запрашивается из браузера после гидратации. На хабе /ru/tarot то же самое: заглушка и ни одной ссылки на страницы раскладов. Главная /ru тоже без H1 и ссылается только на /ru/tarot и правовые страницы.

**Почему важно.** Google увидит контент, только если отрендерит JS и запрос к API успеет выполниться. Это идёт с задержкой и не гарантировано. Яндекс рендерит JS хуже, а ИИ-краулеры (ChatGPT, Perplexity) не выполняют его совсем. Страницы раскладов фактически изолированы: в серверном HTML на них не ведёт ни одна ссылка.

**Что сделать.**

1. Перенести загрузку описательного контента расклада (H1, вводный текст, описание позиций, FAQ) в серверный компонент: fetch в page.tsx или чтение из CMS при сборке. Интерактивную часть (выбор карт, ответ ИИ) оставить клиентской.  
2. Показывать заглушку «Загрузка…» только внутри интерактивного блока, а не вместо всей страницы.  
3. На каждой странице расклада ровно один \<h1\>, разделы текста размечены \<h2\>.  
4. Список раскладов на /ru/tarot рендерить на сервере обычными \<a href\> (компонент next/link). С главной добавить ссылки на основные расклады.  
5. Добавить хлебные крошки: Главная → Расклады Таро → название расклада.

Проверка: curl \-s https\://kaelisai.com/ru/tarot/dreams \| grep '\<h1' возвращает H1, в ответе есть текст расклада; curl \-s https\://kaelisai.com/ru/tarot \| grep 'href="/ru/tarot/dreams"' находит ссылку.

## **Задача 7\. Редиректы локалей**

**Сейчас.** Middleware считает неизвестную или заглавную локаль частью пути и дописывает к ней /en. Получается временный редирект на несуществующую страницу.

| Запрос | Ответ | Итог |
| :---- | :---- | :---- |
| /RU/tarot/dreams | 307 → /en/RU/tarot/dreams | 404 |
| /es/tarot/dreams (то же для de, pt, fr, uk) | 307 → /en/es/tarot/dreams | 404 |

**Что сделать.**

1. Локаль в другом регистре → 308 на ту же локаль в нижнем регистре: /RU/... → /ru/....  
2. Код uk (язык из hreflang) → 308 на /ua/..., чтобы ссылки по коду языка не ломались.  
3. Остальные неподдерживаемые локали → сразу 404 или 308 на /en/\<остаток пути\> без префикса неизвестной локали.  
4. Редиректы по выбору языка пользователя (cookie NEXT\_LOCALE, Accept-Language) применять только к URL без локали, например к /. URL с явной локалью всегда отдавать как есть, без редиректа.

## **Задачи 8–9. Мета-теги, Open Graph, разметка**

**Сейчас.** Мета Title и мета description собираются по одному шаблону для всех раскладов: «\<Название\> — Ежедневные точные онлайн-расклады карт от 🌑 Kaelis 🌑 Ваш ИИ-проводник в мир Таро». Эмодзи в сниппете Google часто вырезает, а текст не отвечает на запросы конкретной страницы. Тегов Open Graph и Twitter Card нет, разметки JSON-LD нет.

**Что сделать.**

1. Вынести мета title, description и H1 в поля справочника раскладов, чтобы SEO-специалист мог задавать их для каждой страницы и локали. Шаблон оставить только как запасной вариант.  
2. Длина title до 60 символов, description до 160, без эмодзи.  
3. Значения для /ru/tarot/dreams (на основе семантического ядра):  
   * title: «Сонник ИИ онлайн — толкование снов по картам Таро \| Kaelis»  
   * description: «Опишите сон — нейросеть Kaelis сделает расклад Таро и расшифрует его значение. Бесплатно, онлайн, без регистрации.»  
   * H1: «Толкование снов с помощью Таро и искусственного интеллекта»  
4. Добавить og:title, og:description, og:image (1200×630), og:url, og:locale и twitter:card через metadata.openGraph и metadata.twitter.  
5. Добавить JSON-LD в серверный HTML: Organization и WebSite в layout, BreadcrumbList на страницах раскладов, FAQPage там, где есть блок FAQ.  
6. Шаблон страницы ошибки отдавать с lang текущей локали, а не en.

## **Задача 10\. Кэширование**

**Сейчас.** Страницы отдаются с cache-control: private, no-cache, no-store и x-vercel-cache: MISS при повторных запросах. Каждый заход, в том числе бота, рендерится заново на сервере. На момент проверки ответ шёл около 0,27 с, но под нагрузкой и после переноса контента на сервер время будет расти.

**Что сделать.** Для хаба и страниц раскладов включить статическую генерацию с ревалидацией (generateStaticParams \+ export const revalidate \= 3600 или по webhook из CMS). Динамика нужна только интерактивному блоку с ответом ИИ, его можно грузить на клиенте.

Проверка: повторный запрос возвращает x-vercel-cache: HIT.
