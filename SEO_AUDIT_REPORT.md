# Финальный аудит SEO-ТЗ

Дата проверки: 12 ноября 2026 года.

## Итог

Исправления по выявленным несоответствиям реализованы и проверены. Изменения по `robots.txt` не требуются: публичный SEO-контент загружается server-only loader напрямую с backend во время build/ISR, а `/api/kaelis/*` используется только интерактивным клиентским flow.

## Проблемы

### 1. API закрыт в `robots.txt` — не подтверждено

- Исследование `D:\Downloads\1.jpg` и `D:\Downloads\2.jpg` подтверждает, что требование относилось к прежней клиентской архитектуре. В текущей архитектуре поисковый робот получает H1, описание и ссылки из server-rendered HTML; backend вызывается напрямую server-only loader, не через путь сайта `/api/`.

### 2. На странице расклада отсутствует API-описание — исправлено

- Пункт ТЗ: 5.
- Критичность: P0 / высокая.
- Исправление: выбранный spread, включая default spread страницы категории, передаёт `description` в существующий hero и рендерится сервером.
- Уточнение: `TarotListItemResource` предоставляет `description` spread и `matrix` с координатами. Описаний позиций в нём нет. `CardResource.description` API описывает карту сгенерированного персонального расклада, поэтому не является статическим SEO-текстом и не выводится на публичной странице.

### 3. Локализованная 404 фактически не применяется — исправлено

- Пункт ТЗ: 9.
- Критичность: P1 / средняя.
- Исправление: отключён экспериментальный global 404, обходивший дерево маршрута. `not-found.tsx` под `[locale]` теперь рендерится в locale layout с корректными `lang`, локализованным текстом и автоматическим `noindex` от Next.js.

### 4. Ошибка API не прерывает build — исправлено

- Пункт: задача 10, дополнительное условие `SEO_IMPLEMENTATION_PLAN.md`.
- Критичность: P2 / средняя.
- Исправление: перед `next build` запускается независимый валидатор публичного каталога для `en`, `ru`, `uk`, всех категорий и spreads. Он использует тот же origin, Bearer token flow, заголовки и проверку контракта; любой сбой завершает build с ненулевым кодом. Server-loader продолжает выбрасывать ошибку при ISR, поэтому неполный ответ не публикуется.

### 5. На странице расклада отсутствуют серверные описания позиций — не исправлено

- Пункт ТЗ: 5.
- Критичность: P0 / высокая.
- Фактическое поведение: `/ru/tarot/dreams` содержит один H1, lead из API, хлебные крошки и FAQ, но не содержит серверных секций с описаниями позиций расклада.
- Ожидаемое поведение: описательный контент расклада, включая описания позиций, должен рендериться серверным компонентом; текстовые разделы должны быть размечены через `h2`.
- Причина: `TarotListItemResource` предоставляет описание расклада и `matrix`, но не предоставляет статические описания позиций. `CardResource.description` относится к карте персонального AI-расклада; локального структурированного источника статических описаний позиций в проекте нет.

## Выполненные проверки

- Получено и сопоставлено исходное ТЗ из опубликованного Google Docs, `SEO_IMPLEMENTATION_PLAN.md` и текущий код.
- API-документация проверена через Playwright: публичные category/spread содержат `site_description`/`description`; статических описаний позиций API не объявляет.
- Playwright подтвердил исходную проблему global 404 на production URL до исправления, а после исправления локально подтвердил API-description в response `/ru/tarot/dreams` и локализованную 404 `/ru/tarot/dreams-xyz` (`404`, `lang="ru-RU"`, локализованный текст, `noindex`, без canonical/hreflang).
- Новые unit-тесты lead-description и build validator проходят. `node --test tests/*.test.mjs`: 99 из 104 тестов успешны; 5 тестов `category-page.test.mjs` не запускаются, так как тестовый загрузчик не подменяет импорт `@/components/faq/FaqSection`.
- `tsc --noEmit` успешно завершён. `npm run build` остановлен validator с ненулевым кодом при фактическом `Public catalog authorization failed (500)`, что подтверждает fail-fast поведение.
- `npm run lint`: не завершился из-за нехватки памяти Node (`Zone Allocation failed`); результат ESLint не получен.
- HTTP-проверки локального приложения: robots, sitemap, HTML без JavaScript, metadata, JSON-LD, 404 и locale-редиректы.
- Playwright: проверены фактические H1, хлебные крошки, ссылки, JSON-LD и содержимое страниц `/ru/tarot/dreams` и `/ru/tarot`.

## Итоговый список недостающих или некорректных пунктов

1. Не исправлено, P0: в серверном HTML страниц раскладов отсутствуют статические описания позиций и соответствующие семантические секции `h2`. Отсутствие таких данных в API не отменяет требования ТЗ перенести этот описательный контент в серверный компонент или CMS.
2. Исправлено: локализованная 404 применяется для локализованных URL.
3. Исправлено: сбой загрузки каталога делает `npm run build` ошибочным.
4. `robots.txt` не требует изменений по подтверждённой server-rendered архитектуре.
5. Набор `category-page` тестов остаётся отдельной технической задачей, не относящейся к SEO-исправлениям.
