# Финальный аудит SEO-ТЗ

Дата проверки: 12 ноября 2026 года.

## Итог

SEO-ТЗ реализовано не полностью. Найдено три несоответствия требованиям ТЗ и одно несоответствие дополнительному условию плана реализации. Изменения в проект не вносились.

## Проблемы

### 1. API закрыт в `robots.txt`

- Пункт ТЗ: 1.
- Критичность: P0 / высокая.
- Фактическое поведение: `/robots.txt` содержит `Disallow: /api/`.
- Ожидаемое поведение: API, из которого загружается контент расклада, не должен быть запрещён для краулинга.
- Последствие: поисковый робот не сможет получать разрешённый ТЗ интерактивный/API-контент.

### 2. На странице расклада отсутствует API-описание

- Пункт ТЗ: 5.
- Критичность: P0 / высокая.
- Фактическое поведение: для категории `dreams` текущий backend возвращает у spread `dream` значение `description: «Глубокий разбор сна»`; на `/ru/tarot/dreams` выделенный HTML-элемент описания пуст. Описания позиций матрицы также отсутствуют в HTML.
- Ожидаемое поведение: серверный HTML должен содержать вводный/описательный текст расклада из API и предусмотренные ТЗ текстовые разделы.
- Последствие: индексируемый текст страницы ограничен H1, FAQ и интерактивным блоком.

### 3. Локализованная 404 фактически не применяется

- Пункт ТЗ: 9.
- Критичность: P1 / средняя.
- Фактическое поведение: `/ru/tarot/dreams-xyz` возвращает глобальную Next.js 404 без атрибута `lang` и без локализованного содержания.
- Ожидаемое поведение: 404 использует текущую локаль URL (`ru-RU` в этом примере), содержит локализованный текст и не публикует canonical/hreflang.
- Последствие: не выполняется требование локализации и доступности error-страницы.

### 4. Ошибка API не прерывает build

- Пункт: задача 10, дополнительное условие `SEO_IMPLEMENTATION_PLAN.md`.
- Критичность: P2 / средняя.
- Фактическое поведение: `npm run build` завершился с кодом `0`, несмотря на повторяющиеся ошибки `Public catalog authorization failed (429)` при генерации статических страниц.
- Ожидаемое поведение: при ошибке загрузки публичного каталога build/revalidation завершается ошибкой, а не сохраняет потенциально неполные индексируемые страницы.
- Последствие: есть риск публикации устаревшего или неполного статического SEO-каталога.

## Выполненные проверки

- Получено и сопоставлено исходное ТЗ из опубликованного Google Docs, `SEO_IMPLEMENTATION_PLAN.md` и текущий код.
- `npm run build`: успешно, но с описанными API-ошибками `429`.
- `node --test tests/*.test.mjs`: 96 из 101 тестов успешны; 5 тестов `category-page.test.mjs` не запускаются, так как тестовый загрузчик не подменяет импорт `@/components/faq/FaqSection`.
- `npm run lint`: не завершился из-за нехватки памяти Node (`Zone Allocation failed`); результат ESLint не получен.
- HTTP-проверки локального приложения: robots, sitemap, HTML без JavaScript, metadata, JSON-LD, 404 и locale-редиректы.
- Playwright: проверены фактические H1, хлебные крошки, ссылки, JSON-LD и содержимое страниц `/ru/tarot/dreams` и `/ru/tarot`.

## Итоговый список недостающих или некорректных пунктов

1. Правила `robots.txt` запрещают API контента раскладов.
2. Серверный HTML страницы расклада не выводит описание, доступное из API, и не содержит описаний позиций.
3. Локализованная 404 не используется в фактическом ответе.
4. Сбой загрузки каталога не делает build ошибочным, вопреки условию плана.
5. Набор `category-page` тестов не проходит из-за неподготовленного тестового загрузчика.
